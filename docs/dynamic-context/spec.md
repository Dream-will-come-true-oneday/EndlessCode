# 动态上下文压缩预算 Spec

## 背景

上下文管理的 8 项阈值目前是固定常量，全部按 1,000,000 token 窗口校准。当用户在配置里
把上下文窗口声明为更小的值（例如 128,000）时，自动压缩触发点会被算成负数，系统只记录
一条告警日志然后什么都不做，自动压缩永不发生；工具结果落盘线同样固定在大窗口量级，小
窗口下不会生效，历史只会一路膨胀直到请求被模型拒绝。此外，触发点计算没有扣除本轮输出
预算与工具定义自身占用的 token，即使触发了压缩，剩余余量也可能不足以完成一次回答。

早期开发线（tag `archive/pre-rewrite-test`）有一份按窗口线性缩放的实现，能修掉「永不触
发」，但它与当前主线是无关历史，且在 1M 窗口下会得出与现状不同的数值，不能直接取用。

## 目标

- G1：任意正数窗口下自动压缩都能触发，阈值随配置窗口等比变化，不再出现静默不压缩。
- G2：1,000,000 窗口下的全部阈值数值与改动前逐一相同，已有行为零回归。
- G3：压缩触发判断计入本轮输出预算与工具定义开销，减少「压缩了仍然超限」的情况。
- G4：窗口配置小到无法容纳正常压缩余量时，进入可见的降级模式而不是静默失效。
- G5：token 估算比例随真实模型用量自校准，降低中文与代码混排下的判断偏差。

## 功能需求

- F1：所有压缩相关的限制值由配置窗口推导，包含单条工具结果上限、同消息工具结果聚合上
  限、摘要预留、自动压缩安全余量、手动/紧急压缩安全余量、摘要后近期原文保留量、恢复附
  件单文件上限、本轮输出预留共 8 项。
- F2：每一项的推导方式是「窗口乘以固定比例」，并受一个下限和一个上限约束；上限取值等
  于现行 1M 校准常量，下限保证 32K 级别窗口仍有可用余量。
- F3：工具字节类上限（单条结果、聚合）随窗口线性放大且不设中间封顶，使 1M 窗口恢复到
  现行 250,000 字节与 1,000,000 字节的行为。
- F4：自动压缩触发点 = 窗口 − 本轮输出预留 − 工具定义 token − 摘要预留 − 自动安全余量；
  紧急压缩后的重试安全线用手动安全余量替换自动安全余量，其余相同。
- F5：工具定义开销按其名称、描述与参数结构的实际字节量折算为 token 计入预算。
- F6：触发点、落盘线、近期原文保留量、恢复附件上限在压缩流程、回合循环、会话恢复三条
  路径上使用同一份推导结果，不允许各自重算公式。
- F7：切换模型导致窗口变化后，预算按新窗口重新推导，不使用旧窗口的阈值。
- F8：推导出的触发点不为正数时进入降级模式：仍然执行落盘与摘要压缩，使用下限值作为保
  留量，状态栏与状态命令显示降级标记。
- F9：摘要完成后进行质量校验，校验不达标时收紧近期原文保留量重试一次，仍不达标则按压
  缩失败处理并交由既有熔断逻辑。
- F10：token 估算比例根据模型回报的真实用量做滑动修正，样本过小或比例明显异常时不修正；
  历史被压缩替换后比例回到默认值。
- F11：状态命令可见地报告当前窗口、可用窗口、自动压缩触发点与是否降级。

## 非功能需求

- N1：不引入新的第三方依赖，不新增配置文件字段，比例表内置于代码。
- N2：预算推导是纯函数且结果不可变，同一窗口与同一工具集必须得到完全相同的数值，保证
  提示前缀稳定与可复现测试。
- N3：现有压缩流程架构不变，仍是工具结果落盘、摘要加近期原文、紧急重试、连续失败熔断
  四层，只改变阈值来源与新增质量校验。
- N4：改动受既有单元测试、静态检查与覆盖率门禁约束，覆盖率不得跌破项目设定值。

## 不做的事

- 不把比例表或任何阈值暴露为用户可配置项。
- 不实现增量滚动摘要与压缩前确定性裁剪，不改摘要提示词的分节结构。
- 不实现「根据请求被拒事件反向学习真实窗口」的自校准。
- 不改动模型名到窗口大小的映射，默认窗口仍由协议默认值决定。
- 不改动按计数而非按量纲的常量：近期消息最少条数、恢复附件文件数、预览头部大小、熔断
  次数、请求超限重试参数。
- 不改动各协议客户端的输出 token 上限取值，只把它作为预算扣减项对待。

## 验收标准

- AC1：窗口配为 128,000 时自动压缩触发点为正数，等于 101,760（128,000 减输出预留 5,120、
  摘要预留 12,800、自动安全余量 8,320）；构造估算量越过该触发点的会话，自动压缩实际执行并
  产生压缩事件（对应 F1、F2、F4）。
- AC2：窗口配为 1,000,000 时，8 项推导值中与改动前存在的 7 项常量逐一相等；含新增输出预留
  （40,000）后，自动压缩触发点等于 795_000，紧急重试线等于 845_000（对应 F2、F3、F4）。
- AC3：窗口配为 200,000 时，摘要预留等于 20,000、自动安全余量等于 13,000、单条工具结果
  上限等于 50,000 字节、聚合上限等于 200,000 字节、近期原文保留量等于 10,000、恢复附件
  单文件等于 5,000（对应 F1、F2）。
- AC4：单条工具结果超过推导上限时落盘并替换为预览；同消息聚合超过推导上限时按结果从大
  到小落盘（对应 F1、F6）。
- AC5：窗口配为 1,000 之类的极小值时，压缩仍然执行，状态命令显示降级标记（对应 F8）。
- AC6：切换模型改变窗口后，状态命令报告的触发点随之按新窗口变化（对应 F7）。
- AC7：摘要后估算量超过目标保留线时，收紧近期原文保留量重试一次；两次都不达标时本轮按
  压缩失败处理并计入连续失败熔断（对应 F9）。
- AC8：同一段历史在使用默认比例与经真实用量修正后的比例下估算结果不同，且修正后比例始
  终落在设定夹逼区间内；历史被压缩替换后比例回到默认值（对应 F10）。
- AC9：窗口、可用窗口、触发点、降级标记四项在状态命令输出中可见（对应 F11）。
- AC10：单元测试全部通过，静态检查通过，覆盖率不低于项目门禁值（对应 N4）。
