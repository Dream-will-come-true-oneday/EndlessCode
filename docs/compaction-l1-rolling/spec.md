# 压缩阶梯 L1 确定性裁剪与增量滚动摘要 Spec

## 背景

提交 07b7b34 之后，上下文管理已具备：L0 工具结果落盘（保留头部预览与指针）、全量 LLM 摘要
加近期原文保留、按窗口等比推导的触发预算、压缩质量门（驻留量 / 空摘要 / 孤儿工具结果）与
连续失败熔断。仍有三个缺口：

1. 每次自动压缩都把全部历史重新摘要一遍，成本随会话长度线性增长；真实模型评测显示
   全量摘要会丢弃中段事实（10 个可验证事实只保住 8 个，保留率 0.8，低于 0.9 门禁）。
2. 落盘与摘要之间没有本地免费的中间压缩层：重复读取同一文件的旧版本、很久以前已落盘
   的工具结果预览，都原样占着上下文，明明不调模型就能压掉。
3. 窗口配置大于模型真实接受量时（例如配置写 1M、模型只吃 128k），当前只会在请求超限后
   紧急压缩重试一次，然后报错退出，不会从错误中学到真实窗口。

## 目标

- G1：在触发 LLM 摘要之前，先用确定性手段降低驻留量，多数超限在本地免费解决。
- G2：自动压缩改为滚动增量，只摘上次覆盖点之后的新片段并与旧摘要合并，把摘要成本从
  会话长度的线性降为增量，同时减少中段事实丢失。
- G3：滚动摘要状态跨会话恢复可用，恢复会话后继续增量而不是重摘全量。
- G4：请求超限成为窗口校准信号，有效窗口自动收敛到真实值，会话能继续而不是报错退出。

## 功能需求

- F1：历史中同一文件的多次读取，自动压缩时只保留最新一条的原文，旧版本替换为一行指针
  （含文件路径与「已有更新版本」说明），指针行不得拆开其所在的工具调用配对。
- F2：很久以前已落盘的工具结果，自动压缩时把头部预览正文降级为纯指针（保留原始大小与
  落盘路径两行），删除预览正文；近期保留范围内的内容不降级。
- F3：上述本地裁剪只在落盘后估算仍高于自动压缩触发线时执行；执行后仍高于压缩期望驻留量
  才进入 LLM 摘要；本地裁剪全程不产生任何模型调用。
- F4：本地裁剪不得改动已冻结的工具结果替换决策，不得删除近期保留范围内的任何内容，
  不得让工具结果失去对应的工具调用。
- F5：自动压缩维护滚动摘要状态——上一版摘要正文、已覆盖的消息数、摘要轮次；每次只把
  上次覆盖点之后的新片段交给模型，并要求模型输出「旧摘要合并新片段」后的新版摘要。
- F6：滚动摘要状态持久化到会话目录；恢复会话后继续增量；状态文件缺失或损坏时回退为
  一次全量摘要并重建状态，会话不得因此不可用。
- F7：手动压缩与紧急压缩维持现状语义——无条件全量重摘，不走滚动增量，也不做本地裁剪
  升级判断；自动压缩路径才启用本 spec 的阶梯。
- F8：请求超限错误发生时，记录失败时刻的估算量，把有效窗口收敛为「配置窗口与该估算量
  的 0.95 倍中的较小者」，按新窗口重建压缩预算，并向用户提示一次；同一会话内多次触发
  只取更小的窗口；切换模型或重启后复位为配置窗口。
- F9：滚动摘要产物必须通过既有压缩质量门；首次压缩（无历史状态）与全量回退路径行为与
  现状一致。

## 非功能需求

- N1：本地裁剪是纯函数式的确定性变换，同样的历史与预算必须得到同样的结果，便于快照测试。
- N2：摘要状态文件损坏不得导致会话不可用或崩溃。
- N3：不改动 L0 落盘的预览文本契约（golden 快照不动），不改动摘要提示词的既有分节结构，
  只新增「合并模式」所需的注入段。
- N4：现有工程门禁照常生效——全量测试通过、lint 通过、覆盖率不低于 85%。
- N5：本轮所有行为不新增用户配置项。

## 不做的事

- 不做对话历史的树状分支与回放（Pi 式 branch + compaction）。
- 不做由模型主动触发的压缩（压缩仍由预算阈值驱动）。
- 不做提示词级 token 压缩（LLMLingua 一类）。
- 不做子代理上下文隔离与跨会话长期记忆。
- 不改手动 `/compact` 与紧急压缩的语义。
- 不改评测体系；真实模型保留率复测顺延到下一次评测运行，不在本轮范围内。

## 验收标准

- AC1：同一文件读取两次后触发自动压缩，旧版本变为指针行、最新版本保留原文，工具调用
  与结果配对完整，模型可通过指针行里的路径重新读到文件。
- AC2：很久以前已落盘的工具结果被降级为「原始大小 + 落盘路径」两行指针，路径仍指向
  磁盘上的完整内容；近期保留范围内的结果预览不变。
- AC3：构造落盘后估算高于触发线的会话，本地裁剪自动执行且全程零模型调用，裁剪后估算
  量下降；裁剪后仍高于期望驻留量时才看到摘要调用。
- AC4：连续两次自动压缩，第二次的摘要请求只包含上次覆盖点之后的新片段（不含已被上一版
  摘要覆盖的早期消息），且新版摘要保留旧摘要的关键事实。
- AC5：持久化状态在恢复会话后继续生效（第二次压缩仍走增量）；人为损坏状态文件后触发
  压缩，回退为全量摘要一次并重建状态，会话不崩溃。
- AC6：配置窗口 1M、实际 128k 的模型返回超限错误后，有效窗口收敛为约 121_600、预算随之
  重建、用户看到一次提示，紧急压缩后本轮能继续完成；再次触发时窗口不再重复提示。
- AC7：滚动摘要产物通过既有质量门三查；手动 `/compact` 的历史替换结果与改动前语义一致
  （全量重摘）。
- AC8：全量测试通过、lint 通过、覆盖率不低于 85%；mypy 相对基线零新增。
