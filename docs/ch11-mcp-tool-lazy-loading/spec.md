# MCP 工具延迟加载 Spec

## 背景

Endless Code 在连接 MCP Server 后会将所有 MCP 工具的名称、描述和参数定义放入每次 LLM 请求的工具列表。当用户配置多个 MCP Server 时，工具数量可达数十乃至数百，即使对话完全没有使用这些工具，完整 schema 仍会在每轮消耗大量 Token，提前触发上下文压缩。

本功能将 MCP 工具默认作为延迟工具：模型先通过轻量工具目录知道可用名称，需要时通过 `ToolSearch` 激活目标工具，后续请求才携带已激活工具的完整定义。

## 目标

- 大幅减少多 MCP Server、数十个工具场景下的每轮请求 Token 占用。
- 让模型能发现延迟工具，并在调用前明确激活所需的完整工具定义。
- 保持现有 MCP 连接、工具执行、权限判定、Plan Mode 和上下文压缩行为兼容。
- 在固定的 58 个模拟 MCP 工具基准中，全会话工具元数据 Token 消耗较全量加载降低至少 80%。

## 功能需求

- **F1：默认延迟**。MCP Server 连接成功后，其工具默认处于未激活状态；未激活 MCP 工具的描述和参数定义不得出现在发给 LLM 的工具列表中。本地内置工具保持现有全量加载行为。
- **F2：延迟工具指令**。存在未激活 MCP 工具时，系统指令必须告知模型：部分工具需先通过 `ToolSearch` 加载，未加载时不能直接调用。
- **F3：轻量工具目录**。每次模型请求都附加一条不进入会话历史和会话存档的合成 user message，以稳定顺序列出当前所有未激活 MCP 工具的完整名称，不包含描述和参数 schema。当没有未激活工具时，不附加空目录。
- **F4：ToolSearch 始终可用**。只要存在 MCP 工具，`ToolSearch` 就作为轻量本地工具出现在每次 LLM 请求的工具列表中，且自身不需要激活。
- **F5：按需激活**。模型通过 `ToolSearch` 选择目录中的一个或多个完整工具名后，命中的工具加入当前会话的已激活集合；`ToolSearch` 结果需明确返回成功激活、已激活和未命中的名称。
- **F6：下一轮生效**。`ToolSearch` 成功后的下一次 LLM 请求必须在工具列表中携带新激活工具的完整名称、描述和参数定义，并从合成延迟工具目录中移除该名称。
- **F7：激活幂等**。对已激活工具再次执行 `ToolSearch` 不得产生重复定义或错误；已激活工具在当前会话的后续模型轮次及上下文压缩前后持续可用。
- **F8：未激活调用拦截**。如果模型在未经 `ToolSearch` 激活时直接请求某个延迟 MCP 工具，客户端必须拒绝远程执行，并返回需先使用 `ToolSearch` 的可操作错误。
- **F9：会话级状态**。已激活集合只在当前运行中的交互会话内有效，不写入项目配置、用户配置、记忆或会话消息存档；新建会话或重启进程后重置为全部未激活。
- **F10：权限兼容**。`ToolSearch` 只改变客户端的工具可见性，不执行远程操作；激活后 MCP 工具的实际调用仍完整经过现有黑名单、沙箱、规则、权限模式和人工确认链路。
- **F11：Plan Mode 兼容**。Plan Mode 中只能发现和激活标记为只读的 MCP 工具；非只读 MCP 工具不出现在该模式的延迟目录或已激活工具列表中。
- **F12：连接异常兼容**。某个 MCP Server 连接失败、工具名非法或连接在运行中不可用时，不得阻塞其他 Server 和本地工具；已激活工具的远程调用继续沿用现有错误返回语义。

## 非功能需求

- **N1：Token 效率**。在固定 58 工具、多轮请求、仅激活少量工具的可重复基准中，将每轮工具定义和合成目录一并计入后，相对每轮发送全部完整 schema 的基线，全会话 Token 估算值降低不少于 80%。
- **N2：确定性**。延迟工具目录和已激活工具定义的顺序必须稳定，相同工具集合产生相同请求内容，利于 Provider 缓存和测试。
- **N3：协议一致**。Anthropic、OpenAI 及 OpenAI 兼容 Provider 的延迟发现、激活和后续调用行为一致。
- **N4：并发安全**。同一会话内多个工具激活请求不得造成状态丢失、重复定义或集合迭代错误。
- **N5：向后兼容**。无 MCP 配置的项目、现有 MCP Server 配置文件、工具名命名空间与远程调用结果格式保持现有行为。
- **N6：可测性**。目录生成、激活迁移、未激活拦截、模式过滤、Provider 请求与 Token 基准必须有自动化测试覆盖。

## 不做的事

- 不改变 MCP Server 配置格式、连接协议或运输层。
- 不将已激活集合持久化，不在新会话中预加载上次使用的 MCP 工具。
- 不对本地内置工具做延迟加载。
- 不根据工具描述做向量检索、语义检索或 LLM 二次检索。
- 不修改 MCP 工具的执行超时、结果截断、非文本内容处理和权限规则语义。
- 不承诺所有工具数量和激活模式下都恰好降低 82%；性能验收以 N1 的固定基准为准。

## 验收标准

- **AC1（对应 F1、F4）**：配置多个 MCP Server 后发起首次模型请求，工具列表包含本地内置工具和 `ToolSearch`，不包含任何未激活 MCP 工具的完整定义。
- **AC2（对应 F2、F3）**：首次及后续模型请求都能观察到延迟加载指令和按稳定顺序排列的未激活工具名目录；真实会话历史与 JSONL 存档中不出现该合成消息。
- **AC3（对应 F5、F6）**：调用 `ToolSearch` 命中一个未激活工具后，返回成功激活结果；下一次模型请求携带该工具的完整 schema，延迟目录不再列出该名称。
- **AC4（对应 F5、F7）**：一次激活多个工具、重复激活已激活工具、查询不存在的名称时，结果分类正确，已激活集合无重复且其他工具状态不受影响。
- **AC5（对应 F8）**：绕过 `ToolSearch` 直接构造未激活 MCP 工具调用时，远程 Server 没有收到调用，工具结果明确提示先使用 `ToolSearch`。
- **AC6（对应 F7、F9）**：触发上下文压缩后，已激活工具仍在后续请求中可用；新建会话或重启进程后，首次请求重新不携带 MCP 完整 schema。
- **AC7（对应 F10）**：激活一个需要确认的 MCP 工具不会远程执行；随后真实调用时仍会产生现有人工确认请求，拒绝后 Server 不收到调用。
- **AC8（对应 F11）**：Plan Mode 的延迟目录仅列出只读 MCP 工具；激活后请求工具列表仅增加只读 MCP 工具，非只读工具不可通过 `ToolSearch` 激活。
- **AC9（对应 F12、N5）**：无 MCP 配置时不出现 `ToolSearch` 或延迟目录，本地工具和模型请求行为与现有版本一致；单个 MCP Server 失败不影响其他工具。
- **AC10（对应 N1）**：运行固定 58 工具 Token 基准，报告全量基线、延迟加载总量和减少比例，减少比例不低于 80%。
- **AC11（对应 N2、N3、N4、N6）**：相同输入重复构建请求得到相同目录和工具顺序；Anthropic、OpenAI 及 OpenAI 兼容 Provider 的自动化测试均通过，全量测试无回归。
