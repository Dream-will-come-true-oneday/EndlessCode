# Diff 展示与 Checkpoint 回滚 Spec

## 背景

当前 AI 修改文件时存在两个信任与安全缺口：

1. **变更不可见**：`write_file`/`edit_file` 执行时，审批弹窗只展示脱敏后的原始参数（新文件全文或 old/new 字符串），用户无法快速判断改动范围；工具执行结果也只有简短文本，没有结构化 diff。
2. **改错无法回退**：AI 误改、误删文件后，用户只能手动 `git checkout` 或手动恢复。会话内的多次修改没有可跳回的历史点。

主流方案（Claude Code 的 diff 审批 + /rewind、aider 的自动 shadow commit、OpenCode 的 diff 审批）均已将"变更可见 + 随时可回滚"作为标配。

已确认的方向：
- checkpoint 采用 **git shadow commit**（项目为 git repo 时），非 git 项目降级为文件快照目录；
- `/rewind` 支持选择恢复范围：仅文件 / 仅对话 / 两者；
- 审批阶段**强制**展示待执行 diff。

## 目标

- 用户在批准任何文件修改前，能直观看到将要发生的变更（diff）。
- 会话内的每次有副作用的操作都有可恢复点，用户可随时跳回任一恢复点，并可选择是否连对话一起回滚。
- checkpoint 机制不污染用户自己的 git 历史，不影响用户正常 git 操作。

## 功能需求

- **F1 审批 diff**：编辑类工具（写文件、编辑文件）触发人工审批时，审批弹窗中展示待执行变更的 unified diff，增删行着色、带少量上下文行；新建文件展示全部内容为新增；diff 过大时截断并提示完整规模。
- **F2 结果 diff 摘要**：编辑类工具成功执行后，工具结果中展示实际变更的精简 diff（变更文件统计 + 关键增删行）；大 diff 截断。
- **F3 自动 checkpoint**：每个有副作用的工具（写文件、编辑文件、bash 等命令执行）执行前自动创建 checkpoint。git 项目下通过专属 shadow ref 记录工作区快照，不出现在用户分支历史和 `git log` 中；非 git 项目降级为快照目录，仅覆盖内置写文件/编辑文件工具（bash 造成的变更不保证可回滚，需明确提示）。
- **F4 /rewind 时间线**：`/rewind` 命令列出本会话的 checkpoint 时间线（序号、时间、触发的工具与目标），用户选择某个点恢复；提供取消出口（不恢复直接退出）。
- **F5 回滚范围选择**：恢复时用户可选择——仅恢复文件 / 仅恢复对话历史 / 文件与对话都恢复。
- **F6 回滚后感知**：仅回滚文件（对话保留）时，AI 在后续轮次能感知文件已被回滚（收到明确通知），避免基于旧认知继续修改。
- **F7 checkpoint 生命周期**：checkpoint 随会话持久化（会话目录），`/resume` 恢复会话后仍可回滚；`/rewind` 面板提供清理本会话 checkpoint 的入口。

## 非功能需求

- N1：checkpoint 创建不显著拖慢工具执行（常规项目单次 < 200ms），大仓库下有降频/跳过策略且行为可预期。
- N2：二进制文件、非 UTF-8 文件不崩溃：diff 展示为占位说明，快照/恢复按字节原样处理。
- N3：不破坏现有五层权限拦截与审计日志；checkpoint 自身的恢复操作也要过权限与审计（恢复文件属写操作）。
- N4：Windows 下路径、编码、git 调用均正常工作（本项目主要运行环境）。
- N5：diff 渲染与复制不冲突——沿用当前"文本可选中复制"的取舍，diff 以带色文本渲染，不牺牲可复制性。

## 不做的事

- 不做跨会话的 checkpoint（回滚仅限当前/已恢复的会话时间线内）。
- 不做语义级代码检索或 diff 智能合并。
- 非 git 降级模式不追踪 bash 命令造成的文件变更。
- 不做 checkpoint 的自动云备份/远端存储。
- 不改动现有 Markdown/RichText 渲染策略（diff 为独立的带色文本渲染）。

## 验收标准

- AC1（F1）：让 AI 修改一个已有文件并触发审批时，弹窗中出现该次修改的 unified diff，增行绿色/删行红色，且本次未批准前文件内容不变。
- AC2（F1）：让 AI 新建一个文件并触发审批时，弹窗展示全部内容为新增行。
- AC3（F2）：批准一次编辑后，聊天区该工具结果处可见变更统计（如 +3/-1）与精简 diff。
- AC4（F3）：在 git 项目中执行一次编辑后，`git log`（当前分支）无新增提交，`git status` 工作区正常，但 checkpoint 存在且可列出。
- AC5（F3）：在非 git 目录中执行一次编辑后，快照目录中出现该文件副本，`/rewind` 能列出该点。
- AC6（F4）：执行 `/rewind` 后出现时间线列表，含序号/时间/触发工具；按 Esc 退出时不发生任何文件变更。
- AC7（F5）：选择"仅恢复文件"后文件回到检查点状态、对话记录仍在；选择"都恢复"后对话也回到该点之前的消息；选择"仅对话"时文件保持当前状态。
- AC8（F6）：仅回滚文件后继续对话，AI 的下一轮回复能体现它已知文件被回滚。
- AC9（F7）：`/resume` 恢复旧会话后执行 `/rewind`，仍能看到该会话历史 checkpoint 并成功恢复文件。
- AC10（N2）：让 AI 编辑一个二进制文件触发审批，界面显示占位说明而非乱码或报错。
- AC11（N4）：在 Windows 项目中完整走通 AC1~AC9。
