# 可配置上下文窗口与动态压缩阈值 Spec

## 背景

当前版本默认按 1M 上下文窗口运行，并将工具结果、摘要余量和恢复附件等阈值固定放大为 200K 基线的 5 倍。这样保留了 1M 能力，但默认成本较高，而且固定常量无法随用户为不同 Provider 选择的窗口变化。

项目已经支持 Provider 级 `context_window` 配置。本次改动将默认值恢复为 200K，同时保留显式 1M 及其他正整数窗口，并让上下文管理阈值根据实际窗口动态计算。

## 目标

- 默认所有 Provider 协议使用 200,000 token 上下文窗口。
- 用户可以在每个 Provider 上配置任意正整数窗口，包含 1,000,000。
- 上下文相关的压缩阈值随实际窗口变化，避免不同窗口共用错误的固定阈值。
- 工具结果保护线适度放大，但不随超大窗口无限增长。

## 功能需求

- **F1：默认窗口为 200K。** Provider 未显式配置 `context_window` 时，Anthropic、OpenAI 和 DeepSeek 均使用 200,000；运行时默认值同步为 200,000。
- **F2：显式窗口优先。** `context_window` 为任意正整数时，运行时使用该值；现有 `0` 表示未配置并走默认值的语义保持不变。配置 1,000,000 时，系统按 1M 运行。
- **F3：token 压缩阈值按比例计算。** 以 200K 为基线，按 `context_window / 200,000` 缩放以下阈值，并向上取整：摘要预留、自动压缩安全余量、紧急重试安全余量、摘要后最近保留 token 数、每个恢复附件的 token 上限。200K 基线值分别为 20,000、13,000、3,000、10,000、5,000；1M 时分别为 100,000、65,000、15,000、50,000、25,000。
- **F4：压缩触发公式跟随动态阈值。** 自动压缩触发点为 `context_window - 摘要预留 - 自动压缩安全余量`；紧急压缩后的重试安全线为 `context_window - 摘要预留 - 紧急重试安全余量`。现有小窗口保护和压缩流程保持不变。
- **F5：工具结果保护线随窗口适度放大。** 以 200K 基线的单条 50,000 字节、同消息聚合 200,000 字节为起点，按窗口比例计算并向上取整，但每项最多放大到基线的 2 倍。因此 1M 及更大窗口使用单条 100,000 字节、聚合 400,000 字节；结果超过相应线时继续落盘并保留预览。
- **F6：配置贯穿所有上下文管理路径。** 新窗口及其动态阈值同时用于 Agent 主循环、TUI 会话恢复、自动压缩、手动/紧急压缩、工具结果落盘、摘要保留和恢复附件限制。
- **F7：文档和示例反映双档使用方式。** README、配置示例和上下文管理章节说明默认 200K，并展示显式配置 1M 的写法及阈值行为。

## 非功能需求

- **N1（兼容性）：** 已有显式 `context_window > 0` 配置继续有效；已有会话 JSONL、恢复流程和 token 估算公式不变。
- **N2（安全性）：** 工具结果保护线在窗口增大后仍有 2 倍封顶，避免单个工具调用无限吞占上下文；完整结果仍可从会话落盘内容恢复。
- **N3（可测性）：** 默认值、显式 1M、任意中间窗口、动态公式、工具阈值封顶和全量上下文路径均有测试覆盖。
- **N4（范围最小化）：** 不引入模型名到窗口的映射，不新增可配置的独立阈值，不改变层 1 落盘、层 2 摘要、熔断、紧急重试和会话恢复的既有流程。

## 不做的事

- 不限制 Provider 只能选择 200K 或 1M；继续接受任意正整数窗口。
- 不把工具结果保护线无限按比例放大到 1M、2M 或更高窗口。
- 不改变 Provider API、会话存档格式、工具命名或 token 估算方法。
- 不新增按工具名称单独配置输出阈值的机制。

## 验收标准

- **AC1：** 未配置 `context_window` 时，Anthropic、OpenAI、DeepSeek 的有效窗口均为 200,000；运行时默认窗口也是 200,000。
- **AC2：** 配置 `context_window: 1_000_000` 时，有效窗口为 1,000,000；配置 512,000 等其他正整数时，原值被保留。
- **AC3：** 200K 窗口的 token 阈值为 20,000/13,000/3,000/10,000/5,000；1M 窗口对应 100,000/65,000/15,000/50,000/25,000；自动和紧急触发公式使用这些动态值。
- **AC4：** 200K 窗口的工具结果线为 50,000/200,000 字节；1M 窗口为 100,000/400,000 字节；更大窗口不超过 100,000/400,000 字节；超限结果落盘并保留预览。
- **AC5：** Agent 运行和会话恢复使用同一窗口配置；构造达到动态自动阈值的会话会触发自动压缩，紧急压缩后的重试判断使用动态安全线。
- **AC6：** 现有显式窗口、会话恢复、工具结果落盘、摘要保留、恢复附件和错误处理测试通过，并新增上述 200K/1M/中间窗口断言。
- **AC7：** README、`.endless-code/config.yaml.example` 及上下文管理文档不再把 1M 描述为默认值，并展示 1M 显式配置。
